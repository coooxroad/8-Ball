# AI 로드맵 (11-18, 소유자: "그렇게 해봐")

샷 심판(`web/ai/60-judge.js`)이 게임의 기반이다. 지금의 한계와, 실제 사례에서 가져온 돌파 방법, 그 순서.

## 지금의 한계 (11-18)

1. **찾아보는 길이 좁다** — 포켓: 직선·뱅크 × 스트로크 9개. 콤비·킥(쿠션 먼저)·3쿠션의 쿠션 먼저 길이 없다 → 최선(B)을
   과소평가 → 등급이 후하고 '더 좋은 샷'을 놓친다.
2. **한 수만 본다** — 실용성 = 다음 샷 상위 3개(1 : 0.33 : 0.15). 9볼 런아웃 순서, 8볼 뭉친 공 풀기, 4구 모아치기 같은
   여러 수의 계획이 없다.
3. **단위가 임의** — "득점 1 + 0.9 × 다음 자리", 이긴 판 2.5. 점수 상황(매치 포인트, 남은 점수)을 모른다.
4. **기준 손이 단순** — 조준·세기·당점이 서로 따로인 정규분포. 실제로는 세게 칠수록, 회전을 줄수록 더 빗나간다.
5. **기준을 봇으로 맞췄다** — 경기력 표·등급 문턱이 봇 경기로 정해졌고, 그 봇은 3쿠션을 비현실적으로 잘 넣는다. 사람 데이터 0.
6. **느리다** — 캐롬 샷당 0.5~0.8초(컨테이너), 폰은 몇 배.

## 사례에서 가져올 것

| 사례 | 무엇을 | 우리 쪽 |
|---|---|---|
| 골프 Strokes Gained (Broadie) | 위치별 기대 타수 기준선(실제 데이터) − 결과, 기준(투어·핸디캡) 고르기, 샷 종류별로 나눔 | 등급이 이미 이 꼴. 기준선을 실제 데이터로, 샷 종류별 손익 코칭 |
| lichess | 평가 → 승률, 정확도 = 승률 하락 | 단위를 "이 판을 이길 확률"로 |
| PickPocket / CueCard (컴퓨터 당구 대회) | 성공률 표, 몬테카를로 2수, 상태 묶기, 브레이크 최적화 | 2수 탐색, 비슷한 결과 자리를 묶어 계산 절약 |
| Stockfish NNUE | 중간 깊이 탐색 평가 수백만 개로 작은 신경망(~50kb) 학습, CPU에서 빠름 | 심판을 오프라인으로 돌려 작은 망으로 증류 → 폰에서 즉시, 더 깊게 |
| Maia (체스) | 레이팅 구간별로 사람 수를 학습 — 약하게 만든 엔진은 사람 수를 35~40%만 맞힘 | 사람 샷 기록으로 레이팅별 손·봇 |
| SCOOT (알토대 2022) | 당구 보상 지형은 뾰족하고 해가 여럿 → 순수 강화학습이 헤맴, 공 여러 개는 못 풂 | 물리 탐색 + 학습한 평가를 섞는다 |

## 순서

1. **샷 기록 수집** — 완료(11-18). `server/src/dataset-core.js`·`dataset.js`: 모든 경기(봇·친구·랭크·초대·대리)의 샷을 계정 없이
   월별 Durable Object에 쌓는다(seats: 레이팅, 사람/봇). 관리자 콘솔 '샷 데이터'에서 현황·내려받기(.jsonl). 개인정보처리방침에 한 줄.
2. **찾아보는 길 넓히기** — 완료(11-18): 킥·콤비네이션(`potExtras`)·3쿠션 빈쿠션(`cushionFirst`), 평범한 길이 약할 때만, 겨냥은 물리로(`judgeAim`).
3. **2수 탐색 + 상태 묶기** — 포켓은 완료(11-18): 마지막 비교에 2수 깊이의 자리 가치(`leaveDeep`), 같은 종류의 결과는 값 하나(`expectOf`). 캐롬은 비용 때문에 아직 1수.
4. **승률 단위** — 완료(11-18): `web/ai/59-win.js`. 남은 공(8볼: 내 공 + 8, 9볼·스누커: 둘이 나눠 쓰는 공)이나 남은 점수로
   두 사람의 경주 — 처음 샷은 자리 가치의 확률, 그다음은 `WIN_Q` — 를 정확히 풀어 승률. 등급 문턱은 종목별로 다시 맞춤(봇 경기의 실수
   분포가 예전과 같게), 경기력 표(`REVIEW_PERF`)도 다시 잼.
4½. **의도와 근거** — 완료(11-18, 소유자: '의도를 구체적으로', 코모도처럼): `web/ai/62-intent.js`. 캐롬 길(물리의 `ev.seq`), 포지션
   (세기만 바꿔 친 수구의 자리 — JPool의 포지션 존), 근거(CueTip이 Alciatore 책의 규칙으로 하듯: 컷·거리·가로막는 공·스크래치·뭉친 공),
   다른 길이 나은 이유. 3쿠션 앞·뒤·옆돌리기 이름은 기준을 확인한 뒤에.
5. **증류(NNUE식)** — 캐롬 자리 가치부터(11-18). 선생님 = 느리고 꼼꼼한 쓸기(`leaveTeach`, 한 자리 0.5초쯤), 라벨은 GitHub Actions
   'Label'(저장소가 공개라 4코어 16대가 무료 — PC방보다 쉽다), 학습은 'Train' 워크플로(`web/tools/net/train.js`, CPU 몇 분, 가중치를
   main에 직접 올림 — 라벨 파일은 Actions 밖으로 받을 수 없다: 이 환경의 프록시가 막음). 런타임은 `ai/56-leave-net.js`.
   결과(11-18, 9만6천 자리씩, 따로 만든 300자리로 잼): 4구 오차 0.386 → 0.083, 3쿠션 0.371 → 0.091(자리 가치 0..1), 한 번에 0.04 ms
   (쓸기는 30~45 ms). 캐롬 심판 샷당 0.6초 → 0.3초. 다음: 같은 식으로 포켓 자리 가치·샷 성공률, 그리고 봇.
6. **어디서 잃었나** — 완료(11-18): 샷마다 잃은 몫을 길 선택·조준·세기·다음 자리·파울로(`parts`), 리뷰 통계에 막대로(숫자 없이).
7. **봇** — 같은 심판으로 샷 선택, 레이팅 다시 맞추기, 샷 기록이 쌓이면 Maia식으로 사람다운 봇.
