# 작업: 사람 같은 컴퓨터 상대 (GPT용)

너는 GitHub 저장소 `coooxroad/8-Ball`의 3D 당구 게임 CUE에 **사람처럼 치는 컴퓨터 상대**를 만든다.
랭킹전에서 기다리는 사람이 없을 때 이 상대가 대신 나온다. 화면에는 **컴퓨터라고 표시하지 않는다** — 이름, 아이콘, DAMA(랭킹
점수)가 있는 한 명의 플레이어처럼 보이고, 그렇게 쳐야 한다. 매칭과 화면 연결은 Claude가 한다. 너는 "어떻게 치는가"만 만든다.

## 0. 먼저 읽을 것
1. `AGENTS.md` 전체. 여기 적힌 규칙이 이 지시서보다 우선이다.
2. `web/ai/` 전체: `00-kit.js`(계획의 형식, 도구), `10-pool.js`(8볼·9볼), `20-carom.js`(3구·4구), `90-plan.js`(입구).
   이 폴더는 **함수 하나의 몸통**이다(파일 이름순으로 이어 붙음, 맨 위 이름이 폴더 안에서 겹치면 안 됨, 들여쓰기 2칸).
3. `web/game.js`: 규칙, `g.mode.evaluate`, `g.vOf(power)`. `web/physics.js`: `P.clone`, `P.strike`, `P.run`, `P.pathClear`.
4. `web/economy.js`: DAMA(30에서 시작, 보통 10~80 사이, 높을수록 잘 침).

## 1. 일의 범위
- 만들 곳: `web/ai/50-human.js`(치는 방식), `web/ai/51-people.js`(사람들: 이름·성향 만들기), `web/test/ai-human.js`(검사).
- 건드리면 안 되는 곳: `web/ai/`의 다른 파일, `web/game.js`, `web/physics.js`, `web/app/`, `server/`, `.github/`.
  다른 파일을 바꿔야 하면 하지 말고 PR 본문에 제안으로 적는다.
- 브랜치 `gpt/human-ai`.

## 2. 지켜야 할 연결 (Claude의 매칭이 이것만 부른다)
```js
// 51-people.js
function personaFor(dama, rand)   // DAMA 근처 실력의 사람 한 명: { name, icon, dama, skill, ...성향 }
// 50-human.js
function humanPlan(persona)       // 지금 차례의 샷: 00-kit.js의 계획 형식 { pos, angle, V, a, b, el, think }
```
- `90-plan.js`가 이미 `g.personas[g.turn]`이 있으면 `humanPlan(persona)`를 부른다.
- 난수는 **`rand()`(00-kit.js)만** 쓴다. `Math.random` 금지. 같은 테이블·같은 씨앗이면 같은 샷이 나와야 한다
  (나중에 서버가 이 상대의 샷을 다시 계산해 확인할 수 있게).
- `persona`는 JSON으로 저장·전송할 수 있는 값만(함수 없음). `skill`은 0~1, DAMA에서 정한다(DAMA 10 → 0.05, 30 → 0.4,
  60 → 0.8, 80 이상 → 0.95 근처, 사이는 매끄럽게). `icon`은 `prefs`의 아이콘 번호 범위 안의 정수.
- 이름: 한국 당구장 손님 같은 닉네임(예시 느낌만: 영문+숫자 아이디, 한글 별명). 실제 유명인·선수 이름 금지, 욕설 금지,
  "봇/AI/컴퓨터" 같은 말 금지. 200개 이상이 고르게 나오게 조합식으로.

## 3. "사람 같다"의 뜻 (가장 중요)
기존 `aiPool`/`aiCarom`은 공을 칠 길을 수학적으로 찾고 오차를 고르게 섞는다. 사람은 그렇지 않다:
- **오차가 상황 따라 다르다**: 먼 공, 얇은 각(컷), 쿠션에 붙은 공, 당점을 많이 준 샷, 세게 친 샷일수록 빗나간다.
  방향 오차와 세기 오차를 따로. 실력이 낮을수록 세기 조절이 특히 나쁘다(너무 세게 쳐서 큐볼이 날아다님).
- **고르는 샷이 사람 같다**: 하수는 눈에 보이는 가장 가까운 공을 노리고, 쉬운 샷만 보며, 포지션(다음 공)을 생각 안 한다.
  고수는 다음 공을 위해 당점과 세기를 고르고, 안 될 때는 수비(상대가 치기 어렵게 남기기)를 한다. 중수는 그 사이.
- **성향**이 사람마다 다르다(persona에 담는다): 공격적/신중한, 세게 치는 버릇, 회전을 좋아함, 생각하는 시간(`think`초,
  어려운 샷일수록 길게, 1.5~12초), 가끔 긴장해서 쉬운 공을 놓침. 같은 사람은 한 경기 내내 같은 성향.
- 4구·3구도 같은 원리: 하수는 가까운 빨간 공에 두껍게, 고수는 쿠션을 쓰고 다음 배치를 생각.
- 절대 하지 않는 것: 일부러 티 나게 엉뚱한 방향으로 치기, 매번 똑같은 세기, 사람이 할 수 없는 정밀함(최고 실력이라도 가끔 실수).

## 4. 성능
- 한 번의 `humanPlan`은 node에서 평균 40ms, 최악 300ms 이하(폰에서 돌아간다). 사본으로 쳐 보기(`P.clone`+`P.run`)는 한 번에
  150회 이하. 실제 테이블(`g.world`)은 절대 바꾸지 않는다.

## 5. 검사 (`web/test/ai-human.js`, `node web/test/ai-human.js`로 돈다)
- 실력이 다른 사람끼리 8볼·4구를 시켜서: DAMA가 높은 쪽이 더 자주 이긴다(예: 20 대 50이면 50이 70% 이상). 씨앗 고정이라 매번 같은 결과.
- 같은 씨앗 → 같은 샷(결정적). 시간 한도(4절). 경기가 400샷 안에 끝난다.
- 사람 같은지 숫자로: 실력별 한 차례에 이어 넣는 평균 개수, 파울 비율, 평균 세기를 표로 찍는다(PR 본문에 붙인다).
  실제 아마추어 감각에 맞게: DAMA 30이면 8볼에서 한 차례 평균 1개 안팎, 고수는 3~5개.
- Claude가 나중에 이 파일을 `web/test/run.js`에 연결한다. 너는 `run.js`를 고치지 않는다.
