# 작업: CUE 스킨 추가 (GPT용)

너는 GitHub 저장소 `coooxroad/8-Ball`의 3D 당구 게임 CUE에 **스킨**을 더한다. 코딩을 모르는 소유자가 태블릿으로 결과를
본다. 아래를 끝까지 읽고 그대로 한다.

## 0. 먼저 읽을 것
1. `AGENTS.md` 전체 (특히 1·2·5·7·8절). 여기 적힌 규칙이 이 지시서보다 우선이다.
2. `web/content/` 의 여섯 파일 맨 위 주석 — 칸(필드) 설명이 거기 있다.
3. `web/ui/README.md` — 카드 그림 규격.

## 1. 일의 범위
- 건드려도 되는 곳: `web/content/*.js`(항목 추가·수정), `web/ui/`(카드 그림 `cue-<id>.webp`, `cloth-<id>.webp`,
  `glove-<id>.webp`), `web/tex/ball-<이름>.webp`(공 표면·무늬·요철), `web/sound/`(스킨 전용 소리).
- 건드리면 안 되는 곳: 그 밖의 모든 파일. 특히 `web/app/`, `web/scene/`, `server/`, `.github/`, `app/src/main/assets/`.
  코드가 고쳐져야만 되는 스킨(새 그리기 방식, 새 효과)이면 **하지 말고** PR 본문에 "필요한 코드 변경"으로 적어 둔다.
- 한 PR에 한 묶음(예: "큐 4종 + 소리"). 브랜치 이름 `gpt/skins-<주제>`.

## 2. 항목 더하는 법
- `id`: 소문자·숫자·`-`. **한번 정하면 영원히 바꾸지 않는다**(서버의 보유 목록이 id로 찾는다). 지운 id를 다시 쓰지 않는다.
- `name`: 한국어. `note`: 카드에 나오는 한 줄 한국어 설명.
- `rarity`: 0 일반 ~ 5 시크릿. 가격은 희귀도로 정해진다(`web/economy.js`: 0, 3000, 8000, 20000, 50000코인, 시크릿 300다이아).
  희귀도가 높을수록 더 눈에 띄고 공들인 디자인. 시크릿은 아주 드물게.
- 색은 `0xRRGGBB`. 큐는 팁부터 부위별 색(`shaft, ferrule, tip, joint, fore, points, wrap, sleeve`) 칸이 모두 있어야 한다(`profile`을 쓰는 큐는 제외, 2-1절).
- 큐의 `spec`(카드를 열면 나오는 표)은 실제 큐처럼 무게·팁·상대·하대·조인트.
- **능력치**(`web/content/00-rarity.js` 맨 위): 큐는 `stat: { power, spin, guide }` — 정수 %, 각각 ±12 안, 셋의 합이 희귀도별
  합계(일반 0, 희귀 4, 에픽 8, 신화 12, 전설 16, 시크릿 20)와 정확히 같게. 하나를 올리면 다른 것을 내려 개성을 준다(예: 파워형,
  회전형). 장갑은 `stat: { power, dial }` — 세기·다이얼이 움직이는 단위, 맨손(2, 0.12)보다 작게, 희귀도가 높을수록 더 작거나 같게.
  규칙이 틀리면 `check.js`가 실패한다.
- 실제 브랜드·선수·로고·캐릭터 이름이나 모양을 쓰지 않는다. 직접 지은 이름과 디자인만.

## 2-1. 모양·재질·빛이 다른 스킨 (Claude가 지원 추가, 코드 수정 없이 데이터와 그림만으로)
공 세트(`30-balls.js`)와 큐(`20-cues.js`)에 아래 칸을 **필요한 것만** 넣는다. 넣지 않은 스킨은 지금 모습 그대로다. 상점 카드의
공 사진과 실제 경기는 같은 모양·재질로 그려진다. 모양은 세트마다 한 번만 만들어 모든 공이 같이 쓴다.

### 공 세트
| 칸 | 뜻 |
|---|---|
| `shape: { lumps, squash, n, eyes, seed }` | 실제로 울퉁불퉁한 3D 모양. `lumps` 혹 깊이(공 반지름의 0~0.15), `squash` 축별 눌림 `[x, y, z]`(각 0.7~1), `n` 혹 개수(기본 12), `eyes` 작은 눈 자국 개수, `seed` 모양을 고르는 정수(바꾸면 다른 감자) |
| `holes: [[위도, 경도, 반지름, 깊이], ...]` | 손가락 구멍. 위도·경도는 도(°) — 경도 90°와 270°가 번호가 찍히는 두 면, 위도 +90이 위쪽 극. 반지름·깊이는 공 반지름에 대한 비율(반지름 0.03~0.4). 구멍은 공과 함께 돌고, 테두리가 빛을 받는다 |
| `skin` | 공의 표면 자체: 그림 이름(`web/tex/ball-<이름>.webp`) 또는 색(`0xRRGGBB`). 이것이 있으면 아래 `mark`로 공을 구분한다 |
| `mark: 'tint' \| 'label'` | 공 구분 방식. `tint`(기본): 표면이 그 공의 색으로 물든다(단색은 전체, 줄무늬는 가운데 띠, 3구·4구의 노랑·빨강은 전체, 흰 공은 그대로) + 번호는 상아색 원판. `label`: 표면은 그대로, 공 색 원판에 번호(줄무늬는 색 고리), 3구·4구는 공 색 원판 두 개(흰 공은 없음) |
| `finish: { rough, coat, metal, bump, bumpScale }` | 재질. `rough` 거칠기 0~1(기본 0.2), `coat` 광택 코팅 0~1(기본 1, 감자는 0), `metal` 0~1, `bump` 요철 그림(`web/tex/ball-<이름>.webp`, 회색조, 밝을수록 높음) |

- 물리는 언제나 같은 크기의 구다. 모양은 **항상 그 구 안쪽**으로만 들어가게 자동으로 맞춘다(가장 튀어나온 곳이 반지름).
  그래서 공끼리 파고들어 보이지 않는다. 대신 `lumps`가 크면 공 사이·천과의 틈이 보이니 0.06~0.1을 권한다.
- 번호·색 구분은 8볼·9볼(번호, 단색/줄무늬)과 3구·4구(흰·노랑·빨강)에 모두 자동으로 적용된다. 노랑·빨강 색은 `yel`, `red`,
  흰 공은 `cue`, 8볼 공 색은 `pal`(없으면 기본 색) 칸을 그대로 쓴다.
- 표면 그림 규격: `web/tex/ball-<이름>.webp`, **2:1 등장방형(equirectangular)**, 1024×512 권장(최대 2048×1024), 이음매 없이
  좌우가 이어질 것. 위·아래 끝이 극이라 늘어나므로 극 근처에는 큰 무늬를 피한다. 번호 원판은 경도 90°·270°(그림의 가로 1/4, 3/4
  지점) 가운데에 그려지니 그 둘레는 비워 두면 좋다. 컬러 표면(`skin`)은 그대로, 기존 `mat`(회색 무늬)은 색 위에 겹쳐진다.
- 요철 그림(`finish.bump`)도 같은 등장방형 회색조. 구멍이 있는 세트는 구멍 요철을 Claude 코드가 자동으로 만들고 `bump` 그림은 쓰지 않는다.

### 큐
| 칸 | 뜻 |
|---|---|
| `profile: [[from, to, r0, r1, 색, { rough, metal }], ...]` | 큐를 팁부터 구간으로 직접 정한다(m 단위, 0부터 1.3~1.6까지 이어서, 반지름 0.003~0.03). 있으면 `shaft` 등 8색 칸은 필요 없다 |
| `glow: { from, to, color, core, r }` | 빛나는 날. `from`~`to` 구간에 밝은 심(`core`, 기본 흰색) + `color` 빛 테두리 두 겹. `r` 심 반지름(기본 0.0062) |
- 세기 게이지 안의 큐 그림도 같은 `profile`·`glow`로 그려진다. 상점 카드 그림 `ui/cue-<id>.webp`는 여전히 필요하다.

### 예시 세 가지 (그대로 넣으면 동작한다; 그림이 생기면 `skin`을 그림 이름으로 바꾼다)
```js
// 알감자: 실제로 울퉁불퉁, 무광, 공 색은 원판으로
{ id: 'potato', name: '알감자', rarity: 3, note: '울퉁불퉁 갓 캔 알감자', pal: null, cue: 0xe9dcc0, yel: 0xf2c21a, red: 0xd3241c, dots: false,
  skin: 0x9a6b3c /* 그림이 생기면 'potato' */, mark: 'label', shape: { lumps: 0.09, squash: [1, 0.86, 0.94], n: 14, eyes: 7, seed: 5 },
  finish: { rough: 0.85, coat: 0 } },
// 볼링공: 마블 무늬 + 손가락 구멍 3개 (번호 면을 피해 위쪽에)
{ id: 'bowling', name: '볼링공', rarity: 3, note: '마블 무늬, 손가락 구멍 셋', pal: null, cue: 0xf4efe2, yel: 0xf2c21a, red: 0xd3241c, dots: false,
  mat: 'marble', holes: [[52, 80, 0.15, 0.3], [52, 100, 0.15, 0.3], [30, 90, 0.17, 0.32]], finish: { rough: 0.15, coat: 1 } },
// 광선검 큐: 금속 손잡이 + 빛나는 상대 (stat은 희귀도 합계 규칙대로)
{ id: 'saber', name: '광선검', rarity: 5, note: '…', stat: { power: 8, spin: 6, guide: 6 },
  profile: [[0, 0.74, 0.006, 0.0062, 0xffffff], [0.74, 0.8, 0.0125, 0.0125, 0x2b2d31, { metal: 0.9, rough: 0.3 }],
            [0.8, 1.3, 0.0128, 0.0132, 0x9aa0a8, { metal: 1, rough: 0.25 }], [1.3, 1.45, 0.0134, 0.0136, 0x1b1c1f, { rough: 0.8 }],
            [1.45, 1.47, 0.0136, 0.013, 0x9aa0a8, { metal: 1, rough: 0.2 }]],
  glow: { from: 0.004, to: 0.74, color: 0x31a8ff, core: 0xeaf6ff, r: 0.0055 } }
```
- 네가 만들 자산: 감자 껍질 `tex/ball-potato.webp`(갈색 껍질, 작은 눈, 흙 자국, 2:1), 원하면 감자 요철 `tex/ball-potato-bump.webp`,
  볼링공 마블(지금 `marble`을 써도 되고 새 그림도 됨), 광선검 카드 `ui/cue-saber.webp`(2400×110, 손잡이 오른쪽, 날이 빛남),
  소리(선택: 감자 `sound.tone` 낮게·`gain` 작게, 볼링공 무거운 소리, 광선검 윙 소리).
- `check.js`가 새 칸의 범위·그림 파일 존재를 검사한다.

## 3. 카드 그림
- 큐 `web/ui/cue-<id>.webp`: 2400×110, 팁이 왼쪽, 투명 배경, 그 큐의 색과 부위가 `content`의 색과 맞을 것.
- 테이블 `web/ui/cloth-<id>.webp`, 장갑 `web/ui/glove-<id>.webp`: 같은 종류의 기존 그림과 크기·구도·빛을 맞춘다.
- 공통: 실제 제품 사진 같은 질감, **빛은 오른쪽 위**, 글자 없음, 약간의 사용감. 과한 광택·금박·완벽한 대칭·장식은 안 된다
  (소유자가 "AI 같다"고 거절한다). WebP, quality 86~88.
- 그림을 직접 만들 수 없으면: 그림마다 **영어 이미지 프롬프트**(크기, 투명 영역, 빛 방향, 재질)를 PR 본문에 쓰고, PR은
  초안(draft)으로 둔다. 소유자가 그림을 만들어 넣으면 그때 완성한다. 그림 없이 검사는 통과하지 못한다(`check.js`가 잡는다).

## 4. 스킨별 소리 (큐·공 세트)
- 항목에 `sound: { rate, tone, gain }`(음높이·밝기·크기, 1이 녹음 그대로, 0.5~1.6 안에서) 또는 `sound: { file: '<이름>' }`.
- `file`을 쓰면 `web/sound/<이름>.mp3`(또는 .ogg/.wav)를 넣는다. 0.3초 안팎, 앞 무음 없이 바로 소리, -1dBFS 넘지 않게,
  모노 44.1kHz, 30KB 이하. 직접 합성했거나 자유 이용 허락(CC0 등)인 것만. 출처를 PR 본문에 적는다.
- 공 세트 소리 = 공끼리 부딪는 소리, 큐 소리 = 큐가 공을 치는 소리.

## 5. 올리기 전 검사 네 가지 (순서대로, 모두 통과)
```sh
node web/test/run.js
sh web/build.sh
node web/tools/check.js
node web/test/browser/smoke.js
```
검사를 지우거나 약하게 바꾸지 않는다. 브라우저 검사를 돌릴 수 없는 환경이면 "smoke 못 돌림"이라고 PR에 적는다.

## 6. PR
- 제목: `스킨: <묶음 이름>`. 본문 첫 줄: 건드린 파일 목록.
- 본문: 더한 항목 표(id, 이름, 희귀도, 한 줄 설명), 그림(만들었으면 미리보기, 못 만들었으면 영어 프롬프트), 소리 출처,
  검사 결과, 실기기에서 못 본 것("확인 못 함").
- 커밋은 작게(항목 묶음 하나 = 커밋 하나). `main`에 직접 올리지 않는다.
