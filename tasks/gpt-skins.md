# 작업: CUE 스킨 추가 (GPT용)

너는 GitHub 저장소 `coooxroad/8-Ball`의 3D 당구 게임 CUE에 **스킨**을 더한다. 코딩을 모르는 소유자가 태블릿으로 결과를
본다. 아래를 끝까지 읽고 그대로 한다.

## 0. 먼저 읽을 것
1. `AGENTS.md` 전체 (특히 1·2·5·7·8절). 여기 적힌 규칙이 이 지시서보다 우선이다.
2. `web/content/` 의 여섯 파일 맨 위 주석 — 칸(필드) 설명이 거기 있다.
3. `web/ui/README.md` — 카드 그림 규격.

## 1. 일의 범위
- 건드려도 되는 곳: `web/content/*.js`(항목 추가·수정), `web/ui/`(카드 그림 `cue-<id>.webp`, `cloth-<id>.webp`,
  `glove-<id>.webp`), `web/tex/ball-<mat>.webp`(공 표면 무늬), `web/sound/`(스킨 전용 소리).
- 건드리면 안 되는 곳: 그 밖의 모든 파일. 특히 `web/app/`, `web/scene/`, `server/`, `.github/`, `app/src/main/assets/`.
  코드가 고쳐져야만 되는 스킨(새 그리기 방식, 새 효과)이면 **하지 말고** PR 본문에 "필요한 코드 변경"으로 적어 둔다.
- 한 PR에 한 묶음(예: "큐 4종 + 소리"). 브랜치 이름 `gpt/skins-<주제>`.

## 2. 항목 더하는 법
- `id`: 소문자·숫자·`-`. **한번 정하면 영원히 바꾸지 않는다**(서버의 보유 목록이 id로 찾는다). 지운 id를 다시 쓰지 않는다.
- `name`: 한국어. `note`: 카드에 나오는 한 줄 한국어 설명.
- `rarity`: 0 일반 ~ 5 시크릿. 가격은 희귀도로 정해진다(`web/economy.js`: 0, 3000, 8000, 20000, 50000코인, 시크릿 300다이아).
  희귀도가 높을수록 더 눈에 띄고 공들인 디자인. 시크릿은 아주 드물게.
- 색은 `0xRRGGBB`. 큐는 팁부터 부위별 색(`shaft, ferrule, tip, joint, fore, points, wrap, sleeve`) 칸이 모두 있어야 한다.
- 큐의 `spec`(카드를 열면 나오는 표)은 실제 큐처럼 무게·팁·상대·하대·조인트. 능력치는 넣지 않는다(곧 Claude가 따로 넣는다).
- 실제 브랜드·선수·로고·캐릭터 이름이나 모양을 쓰지 않는다. 직접 지은 이름과 디자인만.

## 3. 카드 그림
- 큐 `web/ui/cue-<id>.webp`: 2400×110, 팁이 왼쪽, 투명 배경, 그 큐의 색과 부위가 `content`의 색과 맞을 것.
- 테이블 `web/ui/cloth-<id>.webp`, 장갑 `web/ui/glove-<id>.webp`: 같은 종류의 기존 그림과 크기·구도·빛을 맞춘다.
- 공통: 실제 제품 사진 같은 질감, **빛은 오른쪽 위**, 글자 없음, 약간의 사용감. 과한 광택·금박·완벽한 대칭·장식은 안 된다
  (소유자가 "AI 같다"고 거절한다). WebP, quality 86~88.
- 그림을 직접 만들 수 없으면: 그림마다 **영어 이미지 프롬프트**(크기, 투명 영역, 빛 방향, 재질)를 PR 본문에 쓰고, PR은
  초안(draft)으로 둔다. 소유자가 그림을 만들어 넣으면 그때 완성한다. 그림 없이 검사는 통과하지 못한다(`check.js`가 잡는다).

## 4. 스킨별 소리 (큐·공 세트)
- 항목에 `sound: { rate, tone, gain }`(음높이·밝기·크기, 1이 녹음 그대로, 0.5~1.6 안에서) 또는 `sound: { file: '<이름>' }`.
- `file`을 쓰면 `web/sound/<이름>.mp3`(또는 .ogg/.wav)를 넣는다. 0.3초 안팎, 앞 무음 없이 바로 소리, -1dBFS 넘지 않게,
  모노 44.1kHz, 30KB 이하. 직접 합성했거나 자유 이용 허락(CC0 등)인 것만. 출처를 PR 본문에 적는다.
- 공 세트 소리 = 공끼리 부딪는 소리, 큐 소리 = 큐가 공을 치는 소리.

## 5. 올리기 전 검사 네 가지 (순서대로, 모두 통과)
```sh
node web/test/run.js
sh web/build.sh
node web/tools/check.js
node web/test/browser/smoke.js
```
검사를 지우거나 약하게 바꾸지 않는다. 브라우저 검사를 돌릴 수 없는 환경이면 "smoke 못 돌림"이라고 PR에 적는다.

## 6. PR
- 제목: `스킨: <묶음 이름>`. 본문 첫 줄: 건드린 파일 목록.
- 본문: 더한 항목 표(id, 이름, 희귀도, 한 줄 설명), 그림(만들었으면 미리보기, 못 만들었으면 영어 프롬프트), 소리 출처,
  검사 결과, 실기기에서 못 본 것("확인 못 함").
- 커밋은 작게(항목 묶음 하나 = 커밋 하나). `main`에 직접 올리지 않는다.
