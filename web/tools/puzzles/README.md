# 퍼즐 생성기와 퍼즐 AI

```sh
node web/tools/puzzles/gen.js run --seed 1 --minutes 30   # 작업자 하나: 후보를 만들어 레이팅을 매기고 pool-1.json에 모음 (여러 개를 동시에)
node web/tools/puzzles/gen.js run --seed 2 --minutes 30 --game pocket
node web/tools/puzzles/gen.js write                       # 모든 pool을 합쳐 web/puzzles.js의 list를 새로 씀
node web/tools/puzzles/rate.js                            # 지금 목록을 지금 물리로 다시 매김 (물리·FIND를 바꾼 뒤)
node web/tools/puzzles/rate.js --part 0/2 --out a.json    # 나눠서 (작업자마다 하나) ... 
node web/tools/puzzles/rate.js --merge a.json b.json      # ... 합쳐 puzzles.js에 씀
node web/tools/puzzles/fit.js tries.json                  # 서버의 시도 기록으로 학습 (아래 '학습'); --selftest: 만든 진실로 시험
```

Node 내장 모듈만 쓴다. 물리·판정 사본은 없다 — `lab.js`가 앱·서버와 같은 `physics.js`, `game.js`, `puzzles.js`(setup·judge·play)를 부른다.

## 퍼즐 (owner 11-23/24)

- 단계·주제 없음. 퍼즐마다 `rating`(그 레이팅의 선수의 기대 점수가 0.5인 점)과 `fun`. 앱이 숨은 퍼즐 레이팅 근처에서 고른다(`web/app/52-puzzle.js pzr`).
- 점수(11-24 밤): 기회 세 번 - 1번째 성공 1, 2번째 0.75, 3번째 0.5, 못 풂 0(힌트를 봤으면 최고 0.5). 레이팅은 화면에 없다.
- 종목: 4구(`puzzle4`, 캐롬 테이블), 포켓(`puzzle8`, 늘 7피트 테이블 `pzpool`).
- 800 이하에는 일반 4구 배치만(빨간 공 둘, 조건 없음). 800 위로는 조건이 섞이고, 일반 배치도 어려운 것(난구)은 2,000대까지 나온다.
- 조건: 변형 테이블(`tables.js TABLE_OUTLINES`), 바리케이드, 꼭 맞을 쿠션(`need`, 윤곽 변 번호), 두 턴(`turns: 2`), 목표(모아치기·빈쿠션·쓰리쿠션·쿠션 없이), 포켓은 넣을 공·넣으면 안 되는 공.

## 생성 (`gen.js`)

1. **배치**: 4구 일반은 무작위, 어려운 칸이 비면 난구 배치(빨간 공이 쿠션에 붙음, 큐볼이 쿠션에, 노란 공이 길을 막음, 빨간 공이 양 끝, 빨간 공 둘이 붙음, 큐볼이 구석)를 섞는다. 조건 퍼즐은 조건을 1~2개 고르고, 바리케이드는 가장 쉬운 길을 찾은 뒤 큐볼 길을 가로질러 세운다. 꼭 맞을 쿠션은 답들이 맞는 변 가운데 가장 쉬운 답이 안 맞는 변으로 정한다.
2. **탐색**(`search`): 공을 향한 조준(두께 전체), 쿠션에 비친 공(한 번, 일반 테이블은 두 번), 포켓으로 보내는 고스트볼과 그 반사(킥), 1.5°마다 한 바퀴 × 세기 4개, 공을 향한 조준엔 밀어·끌어·좌우 회전, 바리케이드엔 세운 큐까지.
3. **레이팅**(`ai.js`): 되는 샷들을 길(첫 공, 쿠션 수, 뱅크·콤비, 회전)로 묶고, 쉬운 길 셋을 골라 각 길의 가운데(되는 샷이 가장 많이 모인 곳)로 옮긴 뒤 가상 선수로 매긴다. 레이팅 R인 선수는 길을 볼 확률(`FIND`: 쿠션·회전·세운 큐·요소로 정한 D에서 로지스틱)로 길을 보고, 세 번까지 친다 - 손 오차(1500에서 조준 0.16°·세기 3%·당점 0.05, 400점마다 반으로)가 1번째 ×1, 2번째 ×0.6, 3번째 ×0.4(빗나간 걸 보고 고침), 각 32번 쳐 봄. 기대 점수 = 볼 확률 × [p1 + (1−p1)·p2·0.75 + (1−p1)(1−p2)·p3·0.5]. 여러 길 중 가장 나은 길, 기대 점수가 0.5가 되는 R이 퍼즐 레이팅. 손 오차는 퍼즐마다 한 번 뽑아 모든 R에 같이 쓴다(같은 퍼즐은 늘 같은 레이팅).
4. **재미**: 길에 든 것(쿠션·회전·세운 큐·요소), 뻔한 샷이 안 됨, 길이 한두 개뿐, 답의 여유가 알맞음.
5. **칸 채우기**: 100점 칸(400~2,400)마다 일반 4구 10개, 조건 4구 8개(800 위만), 포켓 6개. 칸마다 1.5배까지 모았다가 `write`가 재미 높은 순으로 남긴다. 칸마다 답의 최소 여유(`MIN_ROOM`: 답 둘레 ±0.6°·±8% 격자에서 되는 비율) - 800 이하 0.45(넓은 답만: 손이 아니라 길 찾기가 문제), 1100 이하 0.3, 1400 이하 0.18, 1800 이하 0.08, 그 위는 제한 없음.
6. **확인**: 저장되는 답(세기는 파워 슬라이더가 낼 수 있는 값으로 맞춤)을 처음부터 앱·테스트·서버와 똑같이(`puzzles.js play`) 다시 쳐서 되는 것만 남긴다. 비슷한 배치(모든 공이 2cm 안)는 하나만.

id: 목록에 남는 퍼즐은 제 id 그대로(서버가 id로 지급·매김), 새 퍼즐은 `next-id.json`의 다음 번호(4구 2001~, 포켓 6001~ - 빠진 퍼즐의 id도 다시 쓰지 않는다). 첫 세트(101~825, 단계식)의 id도 다시 쓰지 않는다. `pool-*.json`은 커밋하지 않는다.

## 학습 (`fit.js`)

서버는 퍼즐이 끝날 때마다(점수 1·0.75·0.5·0) 계정의 퍼즐 레이팅을 Glicko로 움직이고(`server/src/core.js puzzleTry`), 퍼즐 책(`server/src/puzzlebook-core.js`)이 퍼즐도 같은 식으로 다시 매기며 시도를 계정 없이 남긴다(퍼즐 id, 풀었는지, 그때 선수 레이팅). 5번 넘게 시도된 퍼즐은 앱이 그 레이팅으로 고른다(`/v1/puzzles/live`).

```sh
curl -s -X POST https://api.danguuu.com/v1/admin/puzzles -H 'X-Admin-Pass: …' -d '{"after":0,"limit":1000}' > tries.json
node web/tools/puzzles/fit.js tries.json
```

1. 퍼즐마다 시도들이 가장 그럴듯해지는 레이팅(1PL IRT = Elo 곡선, 부분 점수는 무승부처럼, AI 레이팅을 사전분포 sd 250으로).
2. 그 값에서 AI 레이팅을 뺀 것(AI가 틀린 만큼)을 퍼즐 특징으로 릿지 회귀 → 각 요소가 실제 선수에게 몇 점인지(`fit.json`). 이걸로 `ai.js FIND`를 고치고 `gen.js`로 다시 만든다.
